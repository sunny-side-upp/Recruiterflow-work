# Sample feature-explainer script: one connected recruiting workflow

**Format:** 60-second product explainer concept  
**Audience:** Boutique and mid-sized recruiting agencies evaluating an ATS + CRM  
**Purpose:** Demonstrate product-marketing craft across narrative, visual direction and claim hygiene.

> This is a speculative portfolio script, not official Recruiterflow copy. The final video must use the current product UI and approved feature claims. Scenes below are illustrative until validated by Product.

| Time | Voiceover | Visual direction / on-screen copy |
|---|---|---|
| 0–6 sec | “A recruiting day rarely happens in one step.” | Quick cuts across a candidate search, an outreach touchpoint and a client update. On-screen: **Source. Engage. Follow through.** |
| 6–15 sec | “You find a promising candidate, reach out, update the client, and still need to know what should happen next.” | A single candidate card moves through a simple workflow; keep data fictional and clearly illustrative. |
| 15–30 sec | “Recruiterflow brings recruiting workflows across ATS, CRM, sourcing and outreach into one workspace.” | Product-validated screen capture or a guided UI path showing the exact supported actions. On-screen: **A connected recruiting workflow.** |
| 30–42 sec | “That gives your team a clearer place to manage candidate and client context as work moves forward.” | Follow one fictional candidate through a supported workflow, then show the related client record and next step if the current product allows it. |
| 42–52 sec | “Exploring AI-assisted work? See which AIRA capabilities fit your workflow and which plan includes them.” | Show only approved AIRA features and current plan details; do not imply every agent is in every plan. On-screen: **Understand the workflow. Then compare the plan.** |
| 52–60 sec | “See how the workflow fits your team. Book a product walkthrough.” | Brand end-card and a clear demo CTA. Add captions and a descriptive link. |

## Production notes

- Begin with the buyer's day, not a feature list.
- Keep one fictional workflow from beginning to end so the viewer can follow the story.
- Validate every screen, feature name, plan boundary and UI state with Product before recording.
- Do not use unsupported time-saving, placement-rate or revenue claims. Add a customer result only with a source, context and approval.
- Brief the editor to use readable zooms, cursor pacing, captions, and a clear end card. Avoid fast UI cuts that make the workflow hard to understand.
- Measure video completion, CTA click-through and qualified demo conversion; review traffic source and audience fit before attributing results.
